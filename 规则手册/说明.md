# LogCrate 规则手册

每次开启或继续一个需求，都必须完整走完 Step-0 至 Step-4。五个步骤用于判断 OpenSpec 流程、重新建立项目上下文、检查既有工作、确认执行约束并明确验证证据，不能因任务看似简单而跳过。

## 目录

```text
规则手册/
├─ 说明.md
├─ Step-0/
│  └─ OPENSPEC.md
├─ Step-1/
│  └─ 项目配置.md
├─ Step-2/
│  └─ 工作状态.md
├─ Step-3/
│  └─ 执行规则.md
└─ Step-4/
   └─ 验证规则.md
```

## 每个需求的完整步骤

### Step-0：读取 OpenSpec 规则

完整读取 `Step-0/OPENSPEC.md`，先判断当前需求是否触发 OpenSpec。命中 proposal、spec、新能力、破坏性变更、架构或重大性能/安全调整时，继续读取项目 `openspec/AGENTS.md` 和相关 spec/change；未命中时继续 Step-1。

### Step-1：读取项目配置

完整读取 `Step-1/项目配置.md`，重新建立 LogCrate 的 WHAT、WHY、HOW、模块边界、项目命令和关键技术约束。

### Step-2：读取工作状态

每次开启或继续需求时完整读取 `Step-2/工作状态.md`，核对是否存在未完成任务、阻塞、冲突、来源不明的工作区改动或需要恢复的检查点。发现前序任务仍在进行时，不得直接开始新任务。

跨会话、长时间运行、高风险或包含多个未决事项的任务必须持续填写工作状态。执行中采用“发现即记录”：任何尚未处理但可能影响当前或后续工作的事项立即进入发现台账；暂停或结束时在详细交接中逐项列出。任务、需求和验证结论仍以各自权威文档为准，工作状态只保存恢复和交接所需的现场信息。

### Step-3：读取执行规则

完整读取 `Step-3/执行规则.md`，确定最小任务顺序、实施约束、OpenSpec 方案变化处理、工作恢复和自动提交要求。

### Step-4：读取验证规则

完整读取 `Step-4/验证规则.md`，按影响面选择验证等级。每个最小任务必须独立完成实现、测试、交接、任务状态更新和 commit，确认无阻断问题后才能进入下一任务。

## 完成五步之后

1. 读取与当前需求直接相关的代码、测试、配置和专题文档；发现新依赖后再追加资料。
2. 按 Step-3 的顺序逐个实施最小任务，并按 Step-4 完成该任务的验证、交接和独立 commit 后再继续。

规则内容或项目事实与仓库现场冲突时，先停止有影响的操作并完成只读核对；无法消解时请求维护者裁决。
