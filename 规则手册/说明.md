# LogCrate 规则手册

每次开启或继续一个需求，都必须完整走完 Step-0 至 Step-5。六个步骤用于判断 OpenSpec 流程、重新建立项目上下文、确认工作状态约束、检查既有现场、执行任务并明确验证证据，不能因任务看似简单而跳过。

```text

```

## 每个需求的完整步骤

### Step-0：读取 OpenSpec 规则

完整读取 `Step-0/OPENSPEC.md`，先判断当前需求是否触发 OpenSpec。命中 proposal、spec、新能力、破坏性变更、架构或重大性能/安全调整时，继续读取项目 `openspec/AGENTS.md` 和相关 spec/change；未命中时继续 Step-1。

### Step-1：读取项目配置

完整读取 `Step-1/项目配置.md`，重新建立 LogCrate 的 WHAT、WHY、HOW、模块边界、项目命令和关键技术约束。

### Step-2：读取工作约束

完整读取 `Step-2/工作约束.md`，先确定本次任务是否只需核对工作状态，还是必须建立并持续更新可恢复现场；同时明确状态与验证、任务勾选和 Git 提交如何共同闭环。

### Step-3：读取工作状态

完整读取 `Step-3/工作状态.md`，核对是否存在未完成任务、阻塞、冲突、来源不明的工作区改动或需要恢复的现场。发现前序任务仍在进行时，不得直接开始新任务；已由 Git 和有效证据证明闭环的历史记录不阻止新任务。

需要持久化现场时继续使用工作状态的现有结构和“发现即记录”台账；普通问答、只读调查和无未决事项的单一短任务不为记录过程机械改写它。

### Step-4：读取执行规则

完整读取 `Step-4/执行规则.md`，确定最小任务顺序、实施约束、OpenSpec 方案变化处理、工作恢复和自动提交要求。

### Step-5：读取验证规则

完整读取 `Step-5/验证规则.md`，按影响面选择验证等级。每个最小任务必须独立完成实现、测试、交接、适用的状态更新和 commit，确认无阻断问题后才能进入下一任务。

## 完成六步之后

1. 读取与当前需求直接相关的代码、测试、配置和专题文档；发现新依赖后再追加资料。
2. 按 Step-4 的顺序逐个实施最小任务，并按 Step-5 完成该任务的验证、交接和独立 commit 后再继续。

规则内容或项目事实与仓库现场冲突时，先停止有影响的操作并完成只读核对；无法消解时请求维护者裁决。
