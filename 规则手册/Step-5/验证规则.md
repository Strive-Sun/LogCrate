# LogCrate 验证规则

验证目标是在足够证明改动正确的前提下尽快获得反馈。默认选择与影响面相称的最小验证集，不因存在某条命令就每次运行全部测试、完整构建、真机或性能基准。

未选择某项检查不等于跳过门禁：先确定验证等级，再执行该等级要求的检查；要求的检查未运行、失败或无法复核时，不得写成通过。

## 1. 快速反馈循环

1. 每次小改动后先运行最接近改动的秒级定向测试或局部检查。
2. 直接行为通过后，仅在影响面扩大、发现相邻回归或等级要求时增加检查。
3. 任务准备完成时，按最终差异执行一次该等级的完成门禁。
4. 同一轮没有新改动时，不重复运行结果仍有效的昂贵检查。
5. 能用本地定向测试证明的行为，不等待远程 CI、部署或完整安装包。
6. 任务或 OpenSpec 明确指定的验收命令优先于默认等级。

## 2. 小节任务完成门禁

任务文档中每个最小编号任务（如 `1.1`）都是独立闭环。只有依次满足以下条件，才允许开始 `1.2`：

1. `1.1` 的实现和直接测试完整，不混入 `1.2` 内容。
2. 按最终影响面选择 L0–L3，并通过该等级要求的测试、检查和专项验证。
3. 核对测试断言、失败、跳过和未验证项，不能只看退出码。
4. 按 Step-2 判断是否需要持久化工作状态；需要时更新验证现场和详细交接，列出改动、证据、准确结论、未处理问题及下一任务起点，普通短任务则在本轮交付说明中保留这些证据。
5. 当前小节范围内不存在失败、阻断或未分类发现；独立后续问题只有进入“发现即记录”台账并获得明确去向后才不阻断。
6. 任务要求人工或真机验收时，必须取得用户确认；未要求人工验收时由 Agent 根据证据完成门禁确认。
7. 验证和交接通过后才勾选该任务，并按 Step-4 创建只包含该小节相关改动的独立 commit。
8. commit 成功且范围正确后，在交付说明中报告任务编号、验证结果、交接结论和 commit，再进入下一任务。

任一步失败都保持当前小节未完成。不得批量实现多个小节后统一测试、统一交接、批量勾选或合并为一个 commit。

## 3. 验证等级

| 等级 | 适用范围 | 最小完成门禁 |
|---|---|---|
| L0 文档 | 普通文档、注释、说明文字、无行为元数据 | 人工核对内容/路径/命令 + `git diff --check`；OpenSpec 追加对应 strict validate |
| L1 局部低风险 | 文案、CSS、局部国际化、测试夹具、无共享状态的单个组件/函数 | 直接测试或局部人工检查 + 改动文件格式/静态检查；类型可能受影响时追加类型/编译检查 |
| L2 一般功能 | 范围明确的业务逻辑、状态转换、错误处理、单侧 API 或相邻多文件修复 | 直接测试 + 受影响模块回归 + 类型/编译检查 + 改动代码静态检查 |
| L3 核心/高风险 | 核心数据路径、跨边界、跨平台、影响面不明或发布类改动 | 受影响技术栈完整测试、类型/编译、静态检查和构建 + 适用专项验证 |

L0 不要求代码测试或构建；L1/L2 默认不运行完整测试、生产构建、Tauri 构建、真机或性能基准。只有入口、依赖、构建配置、资源加载或产物行为受影响时才追加生产构建。

以下情况直接使用 L3：

- IPC/Tauri 命令、事件、共享类型、公共接口或多模块依赖的核心逻辑。
- 并发、共享状态、持久化、schema、迁移、恢复、权限、安全或资源清理。
- 归档解析、日志索引、全盘搜索、NTFS/MFT/USN、平台文件访问等核心数据路径。
- 工具链、依赖、Tauri 配置、sidecar、安装器、更新、发布、大范围重构或明确要求完整门禁。

只有同时影响前端和 Rust 边界时才要求两侧完整门禁。L1/L2 检查发现相邻回归或无法界定影响面时升级，不为求省时维持低等级。

## 4. 测试与边界选择

- 改变业务逻辑、状态、错误处理、持久化、并发、协议或公共接口时，新增或更新直接测试。
- 缺陷修复优先增加稳定回归用例；无法自动化时记录原因并执行可复现的替代验证。
- 纯重构运行覆盖被移动逻辑的既有测试；发现覆盖缺口时再新增测试。
- 覆盖本次改动的成功路径，以及实际可能受影响的失败或边界路径，不为无关边界机械增加用例。
- 边界从输入规模、生命周期、并发顺序、文件系统、迁移、安全和平台差异中按因果关系选择。
- 测试必须确定、可重复、相互隔离，不依赖执行顺序或真实用户数据，不留下进程、句柄、文件和环境污染。
- 时间与并发测试使用通知、屏障、可控时钟、有界超时或可注入故障点，不以长时间睡眠作为唯一同步方式。

## 5. 按等级选用命令

以下命令从项目根目录执行，是工具箱而不是每次全部运行的清单。

### 文档与 OpenSpec

- 指定 change：`openspec validate <change-id> --strict`。
- 全部 OpenSpec：`openspec validate --all --strict`，仅用于归档、发布或影响多个 change/spec。
- 差异格式：`git diff --check`。

### 前端 TypeScript / React

- 定向测试：`npx tsx --test <test-file> [...]`；完整测试：`npm test`。
- 类型检查：`npx tsc --noEmit`。
- 改动文件 ESLint：`npx eslint <changed-files> --max-warnings 0`；全量：`npm run lint`。
- 改动文件格式：`npx prettier --check <changed-files>`；全量：`npm run format:check`。
- 生产构建：`npm run build`。

### Rust 后端

- 定向测试：`cargo test --manifest-path src-tauri/Cargo.toml <filter>`；完整测试：`cargo test --manifest-path src-tauri/Cargo.toml`。
- 库编译：`cargo check --manifest-path src-tauri/Cargo.toml --lib`；全目标使用 `--all-targets`。
- 格式：`cargo fmt --manifest-path src-tauri/Cargo.toml --all --check`。
- 库 Clippy：`cargo clippy --manifest-path src-tauri/Cargo.toml --lib -- -D warnings`；全目标使用 `--all-targets`。
- Windows 索引服务：`cargo check --manifest-path src-tauri/Cargo.toml --bin logcrate_index_service --features windows-index-service`。
- 归档回归：`cargo test --manifest-path src-tauri/Cargo.toml archive::`。

PowerShell 找不到 Cargo 时定位真实工具链并使用绝对路径；环境不可用属于未验证，不得写成通过。

### 桌面、性能与发布

- Tauri 产物：`npm run tauri:build`，仅用于配置、能力、资源、sidecar、安装器或发布产物改动。
- Windows 归档基线：`.\scripts\windows-archive-baseline.ps1`。
- 启动性能：Release 构建后运行 `npm run startup:bench -- --runs 10`。
- 百万路径搜索：Release 运行 `million_path_search_performance_baseline`，带 `--ignored --nocapture --test-threads=1`。
- 发布与品牌：`npm run release:check`、`npm run brand:check`。

性能基准只用于性能关键路径、明确性能目标或可能回退的改动。真实输入延迟、窗口生命周期、权限和系统句柄只能用真实 Tauri/WebView 或真机验证。

## 6. 常见改动映射

| 改动 | 默认等级 | 说明 |
|---|---:|---|
| 普通文档/注释 | L0 | 不运行代码测试或构建 |
| 文案/CSS/局部国际化/测试夹具 | L1 | 只验证直接效果和改动文件 |
| 单个前端组件、工具函数或 Rust 局部模块 | L1/L2 | 定向测试；类型受影响时追加检查，不默认 build |
| 前端共享状态或跨组件流程 | L2/L3 | 相关回归；触及核心共享边界时全量 |
| IPC、共享 schema、并发、迁移、恢复 | L3 | 相关两侧完整门禁 + 失败路径验证 |
| 归档、索引、搜索、平台权限 | L3 | Rust 完整门禁 + 适用安全、恢复、ignored 或真机验证 |
| 构建、安装、更新、发布 | L3 | 相关完整门禁 + Tauri/目标平台产物验证 |
| 性能关键路径 | L3 | 正确性门禁 + 对应 Release 基准，不运行无关基准 |

## 7. 失败、升级与证据

- 首次失败保留命令、环境、退出码和关键输出，再用更小范围命令诊断。
- 环境不可用、权限不足、超时或平台未覆盖属于未验证；仅当该项是所选等级门禁时阻止完成。
- 不得删除失败测试、弱化断言、吞掉退出码、滥用 skip/ignore、无依据扩大超时或更新基线来制造通过。
- 基于等级判定“不适用”不是绕过，记录一条简短原因即可，不为无关命令逐项举证。
- 后续偶然通过不能抹去首次失败；怀疑 flaky 时保存重复结果和触发条件。

L0/L1 在交付说明中记录改动范围、等级、实际命令或人工步骤、结果，以及未运行昂贵检查的简短原因。L2/L3 或跨会话任务使用下表；真机、性能、安全或发布验证再补充环境、指标和产物路径。

| 范围/等级 | 命令或步骤 | 结果 | 未覆盖项及原因 |
|---|---|---|---|
| | | | |

任务状态必须与实际验证结论一致；等级要求的检查失败或未完成时，不得标记任务完成。
