## Context

LogCrate 现有 `data-theme` 只区分 `light` 与 `dark`，大部分组件通过共享 CSS 变量取得颜色。用户需要的是可独立选择的组件视觉模板，而不是替换现有深浅配色。模板需要覆盖应用框架、顶栏、目录、选项卡、底栏、设置页、弹层和常用控件，同时不能破坏日志正文的等宽排版、字段对齐或虚拟列表测量。

## Goals / Non-Goals

- Goals:
  - 在设置页提供三套有缩略预览、当前状态和键盘语义的模板选择卡。
  - 默认“原生”保持当前视觉完全兼容；另外两套模板具有明显且一致的全局设计语言。
  - 选择即时生效、可靠持久化，并能与深色/浅色自由组合。
  - 使用 CSS 变量和根元素属性集中驱动，避免在业务组件中分散模板判断。
- Non-Goals:
  - 不新增在线主题商店、自定义颜色编辑器、导入导出或第三方主题包。
  - 不改变现有顶栏深浅色切换行为，也不在本 change 中新增跟随系统配色。
  - 不改变日志字体、字号、行高、字段边界、控件排列或窗口布局持久化。

## Decisions

### 模板与配色使用两个正交属性

根元素继续使用 `data-theme="light|dark"` 表示配色，并新增 `data-ui-template="native|aurora|amber"` 表示组件视觉模板。模板选择不重置配色，深浅色切换也不重置模板。

### 使用版本化前端偏好并安全回退

新增纯前端 `UiTemplate` 类型及存储工具，通过独立 localStorage 键保存模板值。缺失、未知值、读取/写入异常均回退或保留最后有效的当前进程值；默认值为 `native`。不引入 Rust 配置、IPC 或 schema 迁移。

### 模板定义

- `native` / 原生：不增加模板覆盖，保持当前变量、边框、圆角和阴影。
- `aurora` / 极光：冷色蓝紫渐变、轻度透明面板、彩色边缘与柔和光晕，强调轻盈和层次。
- `amber` / 琥珀：暖色琥珀与珊瑚强调、实体分层卡片、较清晰的边框与柔和立体阴影，强调温暖和操作可发现性。

两套丰富模板通过新增的语义变量控制面板材质、边框强调、圆角、阴影、控件表面和装饰背景，并对顶栏、侧栏、选项卡、底栏、弹层、设置卡、按钮和输入控件提供有界覆盖。日志正文继续使用现有背景与等宽指标；级别色、错误/警告色、关键词与字段匹配高亮保持现有语义和足够对比度。

### 设置页使用可交互预览卡

设置面板新增“界面模板”分组，三个选项全部同时可见。每张卡包含名称、简短说明、由 CSS 绘制的小型顶栏/侧栏/正文预览和选中标记，整体使用原生 radio 语义。点击或键盘选择后立即更新根属性；不需要额外保存按钮。

### 控制视觉成本与动态效果

模板不加载网络资源、位图或新依赖；装饰效果只使用 CSS。`prefers-reduced-motion: reduce` 下取消模板切换、悬停和装饰渐变动画，但保留选中与焦点状态。窄窗口下三张预览卡纵向排列，设置面板保持视口内滚动。

## Risks / Trade-offs

- 全局 CSS 覆盖可能遗漏局部控件 → 以语义变量为主、关键容器选择器为辅，并在设置、日志、搜索和空工作区场景进行视觉核对。
- 半透明和阴影可能降低文字对比或增加重绘 → 透明度保持轻量，不对日志滚动正文使用滤镜或 backdrop-filter，并验证深浅两种配色。
- 模板样式可能改变几何尺寸 → 禁止模板覆盖日志字体、字号、行高、字段宽度和布局尺寸；直接测试根属性与选择行为，真实浏览器核对关键几何不变。

## Migration Plan

首次升级没有模板记录时使用“原生”，因此现有用户视觉不变。若将来删除或重命名模板，未知值按既定回退逻辑恢复“原生”。回滚旧版本时新增 localStorage 键会被忽略。

## Open Questions

- 无；模板名称、视觉方向、默认值、持久化和与深浅色的关系均由本提案固定，若维护者希望调整需在审批前修改。
