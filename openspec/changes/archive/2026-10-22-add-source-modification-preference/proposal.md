# Change: 增加外部修改处理偏好、无缝重载与手动重新加载

## Why

已打开文件被外部持续写入时（例如正在运行的程序输出日志），应用每次检测到修订都会弹出“文件已修改”确认框，用户只能反复点击，无法专注查看日志。现有“重新加载”还会关闭旧会话、显示加载占位，并把滚动位置、字段筛选和查找状态全部重置，持续写入的日志几乎无法连续阅读。

## What Changes

- 设置面板新增“文件被外部修改时”偏好，提供“每次询问”（默认，保持现有行为）、“自动重新加载”、“不提示也不重新加载”三个选项；选择立即生效并持久化，无效值安全回退“每次询问”。
- “自动重新加载”模式下检测到修订时不弹窗，直接按现有重载语义重新读取：活动条目立即重载，同源其它条目转为休眠；同一源同一时间只允许一个重载在途（提示框、自动、手动三种入口统一串行，进行中的手动/提示框请求在结束后合并执行一次），自动重载失败时保留当前内容且不弹出错误，直到源再次产生新修订才重试。
- “不提示也不重新加载”模式下检测到修订时不弹窗，等同于自动选择“保持当前内容”。
- 活动文本日志条目的所有重新加载（提示框、自动、手动）改为无缝替换（DOCX 预览沿用现有重载流程）：新会话就绪前继续显示旧内容，就绪后保留滚动位置（原本位于末尾时跟随新的末尾）、横向滚动、字段布局、字段筛选条件、显示模式、“显示未解析”与所选编码；重新打开失败时保留旧会话。
- 日志选项卡新增右键菜单，提供“重新加载”和“关闭”；任何模式下都可手动重新加载该选项卡所属磁盘源。
- 外部删除、关闭期间删除的处理与提示保持不变。

## Impact

- Affected specs: `log-workspace`（修改外部修改需求，新增无缝重载与手动重新加载需求）、`application-settings`（新增外部修改处理偏好）。
- Affected code: `src/App.tsx`、`src/components/LogContent.tsx`、`src/components/LogTabs.tsx`、`src/components/SettingsPanel.tsx`、`src/util/`（新增偏好存储模块）、`src/i18n/messages.ts` 及对应前端测试。
- 不改变 Tauri 命令、事件、序列化字段或 Rust 实现；不新增依赖。
