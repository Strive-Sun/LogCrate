## ADDED Requirements

### Requirement: Windows 索引服务可诊断安装与提权修复

系统 SHALL 在 Windows 安装、启动和用户主动修复 LogCrate Index Service 时保留明确的权限边界与失败阶段。安装器 MUST NOT 在服务注册、ACL 更新、启动或安装动作执行失败后仍把安装报告为成功。应用内修复 SHALL 仅在用户显式触发并批准系统 UAC 后，以固定的已安装服务程序和固定参数重新注册服务；GUI 与 WebView MUST 保持普通用户权限。服务不可用或用户取消修复时，系统 SHALL 保留兼容目录扫描和可重试入口，不得伪报快速索引已恢复。

#### Scenario: NSIS 安装服务失败

- **WHEN** NSIS 安装期间服务程序缺失、无法执行或 `--install` 返回非零结果
- **THEN** 安装器显示包含失败结果的阻断性错误并停止成功路径，不自动启动 LogCrate，也不只把错误写入隐藏详情日志

#### Scenario: MSI 安装服务失败

- **WHEN** MSI 的提升 custom action 无法注册、配置或启动索引服务
- **THEN** MSI 将该动作视为安装失败并回滚，不留下一个被报告为安装成功但缺少服务的 LogCrate

#### Scenario: 用户主动重新注册服务

- **WHEN** 搜索页面显示快速索引服务缺失、权限异常或启动失败，且用户点击修复并批准 UAC
- **THEN** 系统只运行 LogCrate 安装目录中的 `logcrate_index_service.exe --install`，等待其完成，随后以普通用户权限验证服务状态与协议握手，成功后重新开始一次索引

#### Scenario: 用户取消 UAC

- **WHEN** 用户点击修复后拒绝或取消系统 UAC
- **THEN** 系统明确显示修复已取消，保留兼容目录扫描和可重试入口，不自动再次弹出 UAC且不显示修复成功

#### Scenario: 服务错误按阶段区分

- **WHEN** 快速 provider 或修复流程遇到服务未安装、访问被拒绝、服务启动失败、启动后 IPC 未就绪或协议不兼容
- **THEN** 界面显示对应阶段的稳定错误类别和可读说明，不再使用“未安装或当前用户无权启动”合并所有原因

#### Scenario: 修复目标不可注入

- **WHEN** 前端调用索引服务修复命令
- **THEN** 前端不能提供可执行文件路径、命令参数或提升目标，后端仅允许固定安装目录中的服务程序执行固定重新注册动作

#### Scenario: 修复失败时兼容扫描继续

- **WHEN** 提权进程失败、服务仍无法启动或握手验证失败
- **THEN** 系统显示准确失败阶段，保持该卷的兼容目录扫描与其它卷搜索可用，并允许用户稍后重新修复或排除该卷
