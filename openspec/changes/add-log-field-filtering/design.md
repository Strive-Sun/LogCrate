## Context

现有日志查看器以原始行号建立索引，前端只读取可视窗口。用户提供的样本展示了多种稳定但不同的布局：

- `[2026-06-05 15:39:01.545 +08:00] [info] [Main] [main] [main.js:681] - message`
- `[0401/172412:ERROR:proxy_service_factory.cc(128)] message`
- `07-14 11:29:29.871 15701 16159 I Ktor : message`

这些日志真正稳定的是文件内字段布局，而不是一套跨文件统一的级别名称。筛选栏如果依据当前布局生成，既能筛选级别，也能筛选时间、PID、线程、模块和来源；但自动识别必须允许人工修正，混合格式也不能被静默误分类。

前端无法只隐藏已加载窗口中的行，否则未加载区域不会参与筛选，虚拟列表总数和关键词查找也会错误。布局分析、候选值统计和匹配行映射因此属于 Rust 日志会话的数据路径。

## Goals / Non-Goals

- 目标：从当前日志的有界代表性样本中识别一个主布局，并生成覆盖完整正文宽度的等宽字段筛选栏。
- 目标：允许用户拖动边界、改名、调整字段类型以及拆分/合并字段，纠正自动识别结果。
- 目标：支持时间范围、离散值单选/多选和文本包含筛选；同列多值 OR、跨列 AND。
- 目标：明确展示并可控制不符合主布局的未解析行。
- 目标：同一文件关闭选项卡或重启应用后恢复最后一个稳定的自动或人工字段布局，且不自动传播到其它文件。
- 目标：快速发布首个可操作布局，不阻塞首屏正文，并以量化端到端延迟和 UI 响应门槛验收。
- 目标：保留原始行号、窗口化读取、增量索引和大日志资源边界。
- 非目标：推断每个字段的业务含义、把不同布局自动关联成统一 schema、支持任意正则解析脚本、SQL/布尔表达式、聚合统计或排序。
- 非目标：把续行或堆栈自动附着到上一条已解析日志；本轮将它们独立归入“未解析”。
- 非目标：将人工布局保存为可命名模板、自动应用到其它同格式文件，或跨重启恢复活动筛选条件。

## Decisions

### 1. UI 布局与对齐

字段筛选栏位于文件选项卡和日志正文之间，不占用底部编码/行数状态栏：

```text
┌────────────── 当前文件选项卡：debug.log ───────────────────────────┐
├────────────── 等宽字段筛选栏（首列覆盖行号区域） ─────────────────┤
│[时间 ▾       ][级别 ▾      ][模块 ▾      ][线程 ▾      ][来源 ▾] │
├────────────────────────────────────────────────────────────────────┤
│              1 │[2026-...+08:00][info][Main][main][main.js:681]...│
│              2 │[2026-...+08:00][warn][Main][main][main.js:700]...│
├────────────────────────────────────────────────────────────────────┤
│[UTF-8 ▾] [结果：仅匹配|高亮] [未解析：显示] [清除] [布局 ▾] 1/99│
└────────────────┴───────────────────────────────────────────────────┘
```

- 筛选栏不为正文行号沟槽保留独立空白；第一个字段从筛选栏左缘开始，其视觉范围同时覆盖下方行号区域和首个日志字段区域。
- 同一布局中的字段控件始终使用相同视觉宽度。先以所有字段的代表性 `displayWidth` 最大值为最长字段宽度，再与完整显示最长字段名、下拉箭头和左右留白所需宽度比较，较大者作为理想统一宽度。
- 当“理想统一宽度 × 字段数”不超过筛选栏可用宽度时，每个字段使用该理想宽度，剩余空间留在字段栏右侧；总长度超过可用宽度时，每个字段使用“可用宽度 ÷ 字段数”的相同宽度平均收缩。收缩后标题空间不足可以省略显示，但字段完整名称仍通过可访问名称和 tooltip 提供，下拉操作保持可用。
- 等宽字段栏固定在当前可见筛选栏范围内，不跟随日志正文的横向滚动；横向滚动只移动正文。视觉等宽不修改字段解析边界、持久化布局或筛选值，拖动分隔柄仍调整对应相邻字段并用正文纵向辅助线表达实际边界。
- 每个字段显示名称和活动条件摘要，例如“级别：2 项”；点击字段打开锚定下拉层。字段之间显示可拖动分隔柄，拖动时正文可显示纵向辅助线。
- 双击字段名或从字段下拉菜单选择“重命名”进入行内编辑；字段菜单只提供与该真实字段直接相关的值筛选、类型、拆分和与左/右字段合并操作。
- 字段筛选栏 MUST 只包含日志字段及其分隔柄。`结果模式`、`显示未解析`、`清除筛选`、`重新自动识别` 和 `清除已保存布局` 均不得作为伪字段或尾部选项出现在该栏。
- 日志底部状态栏在编码选择器右侧依次提供单个“结果模式”下拉框、未解析显示开关、清除筛选按钮和“布局”菜单；结果模式下拉框直接显示当前选中的“仅显示匹配”或“高亮匹配”，布局菜单包含“重新自动识别”和“清除已保存布局”。随后显示筛选/行数状态，文件大小继续右对齐。
- 结果模式默认 `仅显示匹配`。结果模式、未解析开关和活动条件属于当前选项卡筛选状态，不属于持久化字段布局，应用重启后恢复默认且无活动筛选。
- 底栏宽度不足时，全局操作可以收起到一个带活动状态提示的“筛选”菜单，但字段筛选栏仍不得接收这些控件，文件大小和核心进度不得互相遮挡。
- 自动分析尚未完成时显示“正在识别布局”；无法形成可靠主布局时显示单一“正文”字段及“未识别稳定布局”，用户仍可进入字段编辑模式手动划分。

### 2. 筛选结果展示与滚动定位

- 两种结果模式都使用当前日志正文区域和现有虚拟列表，不创建新文件选项卡、侧栏或结果表格。每个返回项仍是完整原始 `LogLine`，不把一行拆成表格单元格，也不改写正文文本。
- `仅显示匹配`：未匹配的已解析行从筛选视图隐藏；匹配行及允许显示的未解析行按原文件顺序紧凑排列。行高保持不变，左侧继续显示原文件一基行号，因此 `18、24、31` 等跳号明确表示中间原始行被筛掉。
- `高亮匹配`：虚拟列表保持全部原始行、连续原始行号和原滚动空间；匹配行增加主题化的整行字段匹配背景，未匹配行与未解析行保持普通背景。高亮颜色不得覆盖日志级别前景色、关键词片段高亮、当前关键词命中或文本选择，且必须在深浅主题下可辨识。
- “显示未解析”只在 `仅显示匹配` 模式决定未解析行是否进入紧凑结果。在 `高亮匹配` 模式中所有原始行始终可见，该开关禁用并说明“高亮模式不会隐藏未解析行”。系统不把未解析行移动到单独分组。
- 应用新条件前记录当前视口中心附近的原始锚点行。若该行仍匹配，则新视图保持其在视口附近；若不匹配，则定位到它之后的第一个匹配行，再无匹配时回退到之前最后一个匹配行。首次启用且没有可用锚点时定位到第一个结果。
- 切换结果模式保留全部字段条件和原始锚点。切换到 `高亮匹配` 恢复完整原始行序列并定位锚点；切回 `仅显示匹配` 再按现有匹配映射生成紧凑视图，不重新扫描相同 generation。
- 清除全部筛选时恢复完整原始行序列、移除全部字段匹配背景，并滚动回筛选前记录的原始锚点附近；若原文件已缩短或锚点不可用，则夹取到当前有效范围。
- 后台构建按原始行号递增发布，所以 `仅显示匹配` 中已显示结果顺序不变，`高亮匹配` 中已扫描行逐步获得背景。状态栏分别显示“筛选中：显示 X / 已扫描 Y / 总计 Z”或“匹配 X / 已扫描 Y / 总计 Z”，完成后报告最终匹配与未解析数量。
- 当前已扫描范围没有匹配但任务尚未完成时显示“正在继续筛选”，不提前宣告无结果。完成后仍为零结果时，`仅显示匹配` 在正文显示“没有符合条件的日志”与“清除筛选”；`高亮匹配` 保留全部行并在状态栏显示“匹配 0 行”。
- 筛选失败时回退为全部日志并恢复原始锚点，不保留一个看似成功但不完整的结果集。

### 3. 字段模型与筛选交互

每个字段包含稳定 ID、名称、起止边界/分隔规则、类型、置信度和来源（自动或用户调整）。支持三种筛选类型：

1. `time`：显示当前已解析范围的最小/最大值，允许设置可缺省的开始和结束；边界为闭区间。开始和结束使用只读日期时间选择控件，点击后打开带月份切换、星期表头和日期格的月历，并提供小时、分钟选择，不接受自由文本。条件值只保存当前字段格式中的日期、小时和分钟，不生成或保存秒、毫秒；后端解析日志字段后把实际时间截断到分钟，再与开始/结束分钟做闭区间比较。界面值显示到分钟，清空任一边界不影响另一边界。选择器初始日期时间优先使用已选边界，其次使用对应的最小/最大统计时间，并提供键盘操作与明确的中英文可访问名称。
2. `level`：显示规范化后的级别候选值、计数和搜索框，允许选择零个、一个或多个值。候选去重和匹配使用 Unicode 不区分大小写比较，展示名称统一使用大写；例如 `info`、`Info`、`INFO` 合并显示为一个 `INFO`，计数为三种写法之和。
3. `discrete`：显示按原始大小写精确去重的候选值、计数和搜索框，允许选择零个、一个或多个值。选择一个就是单选，继续勾选即为多选，不设置互斥的模式开关。
4. `text`：提供包含文本输入；用于正文或候选值基数超过上限的字段，不构建无界完整候选列表。

- 同一 `discrete` 字段选中多个值时使用 OR。例如级别选择 `INFO`、`WARN`，任一值匹配即可。
- 用户可以只启用一个字段，也可以同时启用多个字段；不同字段之间使用 AND。例如“时间在范围内 AND 级别为 INFO 或 WARN AND 模块为 Main”。
- 没有活动条件时显示全部行。“清除全部”清空所有字段条件但保留字段布局、名称和类型。
- `level` 字段按解码后的完整字段文本进行不区分大小写的相等匹配，只合并大小写变体，不做别名映射；例如 `warn` 与 `WARN` 合并，但 `WARN` 与 `WARNING` 仍是两个选项。
- 普通 `discrete` 字段按解码后的完整字段文本精确匹配并保留大小写，避免对模块名、线程名、路径或其它大小写敏感值做错误归并。
- 文本字段默认使用不区分大小写的包含匹配，并提供“区分大小写”选项。

### 4. 自动布局识别

- 后端使用两阶段有界抽样而不是读取整份正文。快速阶段取得最多 256 个非空行或 256 KiB 解码文本后立即生成首个可操作布局；后台阶段在索引增长后从已发布范围均匀补样，总计最多 10,000 个非空行或 8 MiB 解码文本，以先达到者为准。
- 分析器识别稳定的成对括号、重复分隔符、空白列、时间戳、整数 PID/TID、单字母 token 和剩余正文。它基于多行的一致边界/分隔序列形成候选模板，不按 `error` 等具体单词决定字段。
- 覆盖样本中占比最高且至少达到 70% 的候选模板成为主布局；其余样本归入未解析。低于阈值时不宣称自动识别成功，而是回退为单一正文字段并允许手动划分。
- 首个布局显示后，后台补样可以更新候选值、计数和置信度；用户尚未交互时允许以更高置信度模板原子替换一次。用户开始筛选或调整边界后自动冻结字段边界，后台不得造成筛选栏跳动，只能提示存在更高置信度布局并由用户决定是否重新识别。
- 自动字段名称和类型是可编辑建议：识别到日期时间建议 `time`/“时间”，符合常见日志级别形态的单字母或低基数短 token 建议 `level`/“级别”，整数列建议 `discrete`/“字段 N”，末尾剩余部分建议 `text`/“正文”。只有字段类型为 `level` 时才合并大小写变体；单纯把普通字段重命名为“级别”不改变匹配语义。
- 每个字段仍保存其在样本中的代表性显示跨度，作为等宽字段栏计算最长字段理想宽度及辅助线位置的输入；视觉等宽不回写或覆盖实际解析边界。实际提取优先使用已识别分隔规则，固定列模板使用字符边界。宽字符和组合字符的拖动位置必须吸附到有效字符串边界，不得切断编码序列。

### 5. 用户修正与重新解析

- 用户拖动分隔柄后生成新的布局 generation。拖动位置吸附到相邻可见字符或分隔符；新边界不得交叉，也不得产生空字段。
- “拆分”在用户指定位置新增边界；“合并”删除相邻边界。重命名只改显示名称；改变字段类型会清除该字段不兼容的现有筛选条件。
- 用户调整后的布局成为当前选项卡的权威布局。后台按新 generation 从已索引行重新分类，旧布局的晚到分析、候选值和筛选结果不得覆盖新布局。
- 切换编码会使字符边界、字段值和时间解析失效。系统保留用户字段名称与相对边界意图，在新编码生效后重新抽样；无法安全映射时回到最新自动布局并提示用户重新检查边界。

### 6. 未解析行

- 空行、续行、堆栈、截断行、与主模板不一致的行，以及字段时间值无法按当前类型解析的行，进入系统“未解析”集合；系统记录原始行号，不修改正文。
- “显示未解析”默认开启。字段筛选开启时，已解析行按字段条件判断，未解析行由该开关独立决定；关闭后才排除未解析行。
- 状态栏显示“已解析 X 行 / 未解析 Y 行”，下拉说明未解析原因。用户清除全部筛选时恢复显示所有原始行。
- 未解析行不继承上一条日志的字段值。本轮不尝试把 Java/JavaScript 堆栈、换行 JSON 或嵌套日志自动组合成记录。

### 7. 后端分析与筛选视图

- 日志会话维护布局 generation、样本摘要、字段定义、每字段有界候选值/时间范围、已解析与未解析计数、已扫描原始行上界、匹配原始行号向量和构建状态。
- 候选值只为 `discrete` 字段维护；每字段最多保留 1,000 个不同值及计数。超过上限时该字段标记为高基数并改用 `text` 交互，不向前端发送截断后看似完整的列表。
- 设置布局或筛选时在阻塞线程按当前生效编码顺序扫描已发布行，只保存匹配原始行号和有界统计，不复制全部正文。原始索引增长时增量处理新增行。
- 新增获取/修改布局、设置/清除筛选、读取筛选窗口和查询进度的 Tauri 命令，以及包含 `sessionId`、generation、扫描数、匹配数、未解析数和终态的事件。前端适配层继续以 `entryKey` 隐藏真实 session ID。
- `read_filtered_lines(start, count)` 的 `start` 是筛选视图序号，返回的 `LogLine.lineNo` 仍为原始文件一基行号。前端虚拟列表按筛选视图数量和序号缓存。
- 筛选构建期间增量显示已扫描范围的结果和进度。失败时保留原日志会话，提示失败并回退为显示全部，不展示不完整结果为成功状态。
- 后端返回筛选视图中的原始锚点定位结果，使前端能够在筛选条件变化和清除筛选时按原始行号恢复附近位置，而不在前端持有全量行号映射。

### 8. 持久化、生命周期与查找

- 每个日志选项卡保留自己的布局、字段名称、类型、筛选条件和未解析开关。切换选项卡关闭下拉层但不清空状态。
- 后端会话被 LRU 休眠后，前端保留当前应用进程内的选项卡字段状态；重新激活时向新会话重放并重建。关闭选项卡释放布局分析、候选字典和匹配映射。
- 使用独立的版本化本机存储保存最后一个稳定的自动布局或人工确认/修改布局，包括字段边界、名称、类型、布局结构指纹、编码提示和最后使用时间；不保存候选值、匹配行号、日志正文或活动筛选条件。快速阶段的低置信度临时布局不得覆盖已有稳定记录。
- 布局没有单独“保存”按钮。后台布局达到稳定阈值时自动保存；用户完成一次有效的分隔柄拖动、字段重命名、类型修改、拆分或合并后，在新布局通过结构校验时立即以原子写入更新同一文件记录。拖动过程中的中间位置、未确认输入和解析失败状态不得落盘。
- 持久化键使用现有规范化文件身份：裸文件使用规范化绝对路径，归档条目使用规范化外层路径与条目路径组合。因此关闭选项卡或重启应用后重新打开同一文件/条目会恢复布局，另一个路径下即使格式相同也不会自动复用。
- 布局存储最多保留最近使用的 256 个文件，超过后按 LRU 删除最旧记录。未知版本、损坏记录、重复字段、越界边界或非法名称必须安全忽略，不能阻止应用启动或日志打开。
- 打开文件时先恢复保存布局并立即显示筛选栏，同时在后台用快速样本校验结构指纹。文件内容已变更但布局仍匹配时继续使用；明显不匹配时保留记录但暂停应用，提示用户选择“继续使用保存布局”或“重新自动识别”，不得静默覆盖人工配置。
- “重新自动识别”清除当前人工边界/名称/类型并立即启动新 generation；新的稳定自动布局会按正常规则覆盖保存记录。
- “清除已保存布局”只删除该文件的持久化记录，当前打开选项卡的内存布局和正文不立即改变；关闭后再次打开将重新自动识别。用户清除记录后若在当前选项卡再次完成有效布局调整，则该调整会按自动保存规则创建新记录。普通关闭选项卡不得删除记录。
- 字段筛选开启时，当前日志关键词查找只遍历可见筛选视图，并返回原始行号与视图位置；布局或筛选变化时清除当前命中但保留查找输入和选项。
- 具体查找范围跟随结果模式：`仅显示匹配` 只查找紧凑结果中的可见行；`高亮匹配` 因全部原始行可见而保持现有全日志查找范围。切换模式时清除当前命中但保留查找输入与选项。

### 9. 可访问性与错误状态

- 字段按钮、拖动柄、重命名输入、下拉选项、时间范围、未解析开关和清除操作提供中英文标签与键盘操作。
- 键盘用户可用方向键调整分隔柄，使用 Enter 打开字段下拉，Escape 关闭且不改变已应用条件。
- 自动识别、重新解析和筛选失败均在筛选栏或正文空态中显示明确状态，不遮挡日志读取与编码选择。

### 10. 布局生成性能门槛

性能验收区分首屏正文、全新自动布局和已保存布局恢复：

- 首屏正文沿用现有边建边读路径，MUST NOT 等待布局样本、字段候选统计或全文件筛选映射完成。布局未就绪时只显示轻量占位状态。
- 全新布局端到端计时从用户触发打开普通本地日志开始，到字段筛选栏出现首个可操作字段集合为止。在 Windows 本地 SSD、Release 构建和固定参考样本上连续运行 10 次，每种样本至少 9 次不超过 300ms，任何一次不超过 500ms。
- 已保存布局恢复计时从用户触发重新打开同一文件开始，到保存的字段控件可交互为止；连续 10 次至少 9 次不超过 100ms，任何一次不超过 200ms。后台指纹校验不得阻塞控件出现。
- 参考样本至少覆盖方括号应用日志、Chromium/CEF、Android logcat，以及小文件和不少于 1GiB 的大文件。大文件只读取快速阶段的有界样本，因此首个布局延迟不得随文件总大小线性增长。
- 自动补样和筛选构建期间采集 WebView 输入事件延迟，p95 不超过 100ms；不得因追求分析速度占满 UI 线程或无界提高后台并发。
- 性能报告记录设备、Release 产物、文件大小/行数、冷/热缓存说明、每轮“首屏可见”“布局可操作”和“后台稳定”时间、UI p95、样本字节数与峰值内存。任何门槛未达到时，性能任务保持未完成，不得只提高超时或减少样本制造通过。

## Risks / Trade-offs

- 自动布局识别不可能覆盖所有日志；70% 主模板阈值、显式未解析集合和人工修正优先避免伪精确。
- 300ms 首个布局目标要求快速样本和后台完善分层；首个判断可能置信度较低，因此只允许在用户交互前原子优化一次，交互后必须保持稳定。
- 按字段重扫大日志具有 IO 和内存成本；使用有界抽样、有界候选字典、generation 取消、后台顺序读取和紧凑行号向量控制资源。
- 等宽字段栏不再逐列表达正文的实际起止位置，用户需要通过字段名称、下拉内容和拖动时的正文辅助线理解字段映射；字段提取始终以保存的分隔规则或字符边界为准，视觉等宽不得修改解析语义。
- 默认显示未解析行能避免数据静默消失，但可能让筛选结果包含堆栈或混合格式内容；用户可显式关闭，状态栏持续报告数量。

## Migration Plan

无需日志、归档或现有工作区 schema 迁移。升级后新增独立的版本化字段布局存储，默认为空且没有活动筛选；布局分析完成前和识别失败时继续显示全部日志。回退旧版本会忽略该存储键，不影响日志与现有工作区。
