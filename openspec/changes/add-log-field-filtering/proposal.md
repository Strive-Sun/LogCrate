# Change: 增加按日志布局生成的字段筛选栏

## Why

不同日志虽然通常具有稳定布局，但字段名称、顺序和级别写法并不统一。仅提供固定 `INFO/WARN/ERROR` 标签既无法覆盖 Android logcat、Chromium/CEF 和应用自定义格式，也容易把正文中的普通单词误判为级别。用户需要直接按当前文件真实存在的时间、级别、进程、线程、模块和来源等字段筛选。

## What Changes

- 在当前日志文件选项卡下方、日志正文上方增加字段筛选栏；不单独保留行号沟槽空白，首个字段从筛选栏左缘开始并覆盖正文行号区域。全部字段控件保持等宽，理想宽度取当前布局中最长字段代表宽度与最长字段标题所需宽度的较大值；可用总宽不足时按字段数量平均缩小。
- 字段筛选栏只容纳由日志内容识别或人工划分出的真实字段，不混入结果模式、未解析、清除或布局管理等系统控件；这些全局操作统一放入日志底部状态栏。
- 系统从有界日志样本中自动识别当前文件的主布局、字段边界和字段类型；支持方括号分段、稳定空白列、冒号等分隔结构和 Android logcat 等常见定宽/半结构化布局。
- 自动生成的字段允许用户拖动边界、重命名、调整类型，并通过拆分或合并纠正识别结果；调整后的字段定义只属于当前文件身份，不自动影响其它文件。
- 当前文件最后一个稳定的自动布局或人工调整布局按规范化文件身份独立持久化；关闭选项卡或重启应用后重新打开同一文件时恢复，但不自动应用到其它文件，也不恢复旧筛选条件。
- 布局采用自动保存，不提供单独“保存”按钮：稳定自动识别完成，或用户完成拖动、重命名、类型调整、拆分/合并后即原子更新该文件记录。布局菜单明确提供“重新自动识别”和“清除已保存布局”。
- 时间字段提供起止范围筛选；级别字段将 `info`、`Info`、`INFO` 等大小写变体合并为一个规范选项；其它低基数字段以下拉候选值筛选；正文或高基数字段提供文本筛选，避免把海量不同正文全部塞入下拉列表。
- 每个离散字段允许选择零个、一个或多个值：同一字段多值按 OR，多个已启用字段之间按 AND；没有活动条件时显示全部日志。
- 日志底部状态栏提供单个结果模式下拉框，选项为“仅显示匹配”和“高亮匹配”，默认“仅显示匹配”。前者在当前日志正文中隐藏未匹配行并紧凑显示保留原始行号的匹配行；后者保留完整原始日志顺序，只为匹配行增加主题化整行背景，不创建新选项卡或结果面板。
- 不符合当前主布局的空行、续行、堆栈或混合格式行归入系统“未解析”集合，并提供独立的显示/隐藏开关，默认显示，避免筛选时静默丢失内容。
- 筛选构建期间增量显示已扫描范围内的结果和匹配进度；“仅显示匹配”完成后无结果时显示空态与“清除筛选”，“高亮匹配”无结果时仍显示全部日志并报告匹配 0 行。清除后移除条件与字段行高亮并返回筛选前的原始行附近。
- 后端按当前字段布局与筛选 generation 流式构建匹配原始行号映射，前端继续窗口读取和虚拟滚动，不把整份日志、全量正文或无界候选值传到前端。
- 字段布局或编码变化时重新解析；日志索引增长时增量分析和筛选；连续调整、休眠或关闭会话时废弃旧 generation 并释放资源。
- 首屏日志显示不等待布局识别；全新文件使用小样本快速生成首个可操作布局并在后台增量完善，已保存布局优先同步恢复。增加新布局、恢复布局和后台分析期间 UI 响应的量化性能门禁。

## Impact

- 受影响规格：`log-viewing`、`log-workspace`。
- 依赖 change：已完成但尚未归档的 `update-log-search-shortcut`；字段筛选开启时关键词查找需要继续只在可见结果中导航。
- 受影响代码：`src/components/LogContent.tsx`、新增字段筛选组件、字段布局持久化与状态工具、`src/styles.css`、国际化、`src/api/`、`src-tauri/src/index.rs`、`src-tauri/src/lib.rs` 及相关测试。
- 新增 Tauri IPC、进度事件、会话内布局/筛选状态和版本化本机布局存储；不改变日志文件、归档内容、权限或网络边界。
