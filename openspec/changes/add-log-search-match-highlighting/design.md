## 背景

现有日志查找由 Rust 基于行索引逐行扫描，每次只返回一个当前方向的匹配位置；前端虚拟列表只渲染可视区域及少量 overscan 行，并用后端返回的 UTF-16 列范围高亮当前匹配。新需求要求同时显示其它关键词，但不能把 GB 级日志全文或全部匹配结果载入前端。

## 目标与非目标

- 目标：正文中所有进入渲染窗口的关键词匹配片段均有黄色背景，当前导航到的关键词片段使用明显不同的主题强调色；不改变整行或其它正文的背景。
- 目标：普通高亮与后端查找的全词、大小写语义一致，并保持 UTF-16 列范围可直接用于 JavaScript 字符串切片。
- 目标：关键词或匹配选项改变时，高亮无需重新扫描整份日志即可更新。
- 非目标：计算全日志匹配总数、创建全部匹配位置索引、正则表达式、替换文本或改变查找方向与循环逻辑。

## 技术决策

- 保留现有 `search_log` 单匹配 IPC。Rust 继续负责跨窗口导航和边界/回绕语义，前端只负责已加载正文的视觉标注。
- 增加纯前端关键词片段范围函数，输入当前渲染行文本、关键词、全词和大小写选项，输出该行内各个不重叠关键词片段的 UTF-16 范围。其字符边界和 Unicode 不区分大小写行为使用与后端一致的测试向量约束。
- `LogRow` 只切分并标注当前渲染行中的关键词片段，不给整行或未匹配文本添加背景，不遍历未渲染行，也不在状态中累计全文件匹配列表。滚动后新进入渲染窗口的行按同一规则即时标注。
- 普通关键词片段使用黄色背景 token；与后端 `findMatch` 的行号和列范围完全一致的关键词片段使用主题强调色与对比文字色。继续查找后，新的关键词成为当前匹配，旧关键词恢复黄色。
- 反向查找与循环查找只决定当前匹配的导航顺序，不改变普通匹配集合；全词和区分大小写选项同时作用于普通高亮和后端导航。
- 查找弹窗打开且关键词非空时显示普通匹配。关闭弹窗后不再计算普通匹配；现有当前匹配标记与滚动位置继续保留，避免改变既有关闭行为。

## 风险与权衡

- 前后端分别执行单行匹配可能产生语义漂移；通过共享边界用例覆盖 ASCII、Unicode、全词、大小写和 UTF-16 代理对，并把差异视为阻断性回归。
- 单行可能包含大量重复匹配；计算范围只针对虚拟列表当前渲染行，且受现有后端超长行截断上限约束，不引入整文件扫描。
- 当前匹配强调色会覆盖日志级别的前景色；仅当前关键词片段使用对比文字色，其余正文继续保留级别着色。

## 迁移计划

无需数据迁移或协议迁移。前端更新后立即使用新高亮规则；回退版本仍可使用现有单匹配查找。
