## Context

DOCX 是基于 OPC/ZIP 的 WordprocessingML 文档。当前统一格式检测会把任何具有 ZIP magic 的文件分派给 `ZipArchiveReader`，目录树因而将 `.docx` 显示为普通归档；现有查看链路则要求读取器提供可流式读取的文本字节，再由行索引和窗口加载消费。

首版的“预览”是正文与常见截图的阅读能力，不是版式渲染器。实现仍须满足 Windows/macOS 一致、用户目录零落地、固定缓冲、实际解码字节限制和损坏输入安全失败等既有约束。现有日志正文是固定 18px 行高的文本虚拟列表，无法在不破坏滚动、行号和筛选语义的前提下承载可变高度图片。

## Goals / Non-Goals

- Goals:
  - 有效 `.docx` 在目录树、拖入和打开链路中表现为一个可直接查看的文档。
  - 主文档正文按稳定、可搜索的结构化段落/表格块输出，内嵌 PNG/JPEG 按文档锚点顺序显示。
  - 文档识别、ZIP/XML 解析和图片读取均使用内容校验、分页与资源上限，不把整份 XML、转换后全文或全部图片一次性载入内存/WebView。
- Non-Goals:
  - 不提供 Word 排版、编辑、打印或导出能力。
  - 不完整还原字体、颜色、主题或任意自定义样式；只读取标题、列表和表格结构所需的有限段落/编号元数据，不读取页眉页脚、脚注尾注、批注、公式、图表、嵌入对象、宏或旧 `.doc`。
  - 不支持 EMF/WMF、SVG、GIF、外链图片或其它非 PNG/JPEG 图片，不执行图片链接或活动内容。
  - 不承诺预览与 Word 的分页、字体、视觉换行、浮动坐标、文字环绕或复杂布局一致。

## Decisions

### 专用格式优先于通用 ZIP

当路径后缀为 `.docx` 时，格式注册表先校验 ZIP magic、`[Content_Types].xml`、包关系以及 `word/document.xml`。校验成功才分派 `DocxReader`；后缀为 `.docx` 但结构无效时返回 DOCX 格式错误，不回退为普通 ZIP 或裸文本。普通 `.zip` 行为保持不变，首版不通过内容扫描把无 `.docx` 后缀的 ZIP 自动提升为文档。

这样可以避免把 Word 内部实现泄露为目录树条目，也避免任意 ZIP 因包含同名文件而改变公共行为。

### 单文档条目与独立图文会话

DOCX 格式层列出一个与源文件同名、标记为可预览且不可继续展开的文档条目。打开时创建 DOCX 专用会话，后台顺序解析主文档并生成有界块索引：段落块保存文本缓存偏移与有限语义角色，表格块保存有界行组、单元格段落和合并跨度，图片块只保存关系 ID、包内安全路径、类型、声明尺寸与显示尺寸，不预读二进制。

实施顺序分为格式/库存接线与会话接线两步。格式/库存层先产生 DOCX 文档叶子与可预览类型；拖入阶段只负责验证文件、添加或复用父目录监控、定位并选中文档叶子，不得临时调用 `open_log_session` 创建错误的日志会话。DOCX 专用会话可用后，再由会话接线把目录树点击、到达项和拖入完成信号统一连接到 DOCX 打开入口，从而达成最终的自动图文预览行为。

前端依据打开结果的会话类型选择现有日志视图或 DOCX 图文预览组件。新增分页块命令、按会话/图片 ID 读取图片命令和会话释放路径；图片命令不得接收任意包内路径。现有日志 IPC、字段筛选和编码重建保持原样，DOCX 预览固定 UTF-8 且不显示日志专用编码、字段筛选或行号控件。

### 流式结构化 WordprocessingML 转换

解析器只消费 `word/document.xml` 的事件流：

- `w:t` 文本按文档顺序输出，并遵守 XML 实体解码与 `xml:space="preserve"`；
- `w:tab` 输出制表符，`w:br`/`w:cr` 输出换行；
- 每个普通 `w:p` 输出独立段落块，保留空段落、显式换行和制表符；通过直接段落属性与受限的可选 `styles.xml` 元数据识别普通正文、标题和 1–3 级标题，未知/损坏样式安全回退为普通段落；
- 通过段落 `w:numPr` 与受限的可选 `numbering.xml` 元数据识别常见项目符号和十进制编号；无法解析的编号保留正文并回退为无标记段落，不加载任意字体或图片项目符号；
- `w:tbl` 输出结构化表格行组，`w:tr`/`w:tc` 保持行列，单元格内多个段落保持独立；`w:gridSpan` 映射为横向合并，`w:vMerge` 映射为纵向合并，缺失或冲突跨度安全回退为普通单元格；
- 表格行数或序列化体积超过单块预算时拆成有界连续行组，前端保持一致列宽和边框，不因单个大表格破坏分页、虚拟化或内存上限；
- 只提取主文档的可见 `w:t`，忽略删除文本、字段指令及本 change 非目标部件。

段落、列表项和每个表格单元格同时提供用于查找的纯文本投影；查找不依赖 HTML，也不扫描未请求的图片。前端使用语义化标题/段落/列表与 `<table>`、`<tr>`、`<td>` 渲染，但只还原结构、间距、边框与合并关系，不复制 Word 的字体、颜色、精确列宽或分页。

解析器同时读取 `word/_rels/document.xml.rels`，仅接受包内相对 image 关系。遇到 `a:blip` 的 `r:embed` 时，在当前段落位置生成图片块；`wp:inline` 与 `wp:anchor` 均按其文档锚点顺序显示为块级图片，不实现浮动坐标或文字环绕。`wp:extent` 用于初始纵横比/显示尺寸，最终宽度不得超过预览正文宽度，缺失或异常尺寸回退为图片固有尺寸或安全默认值。

转换器通过有界生产者/消费者通道输出固定大小数据块和块元数据。前端以支持动态测量的虚拟列表只请求视口附近块；图片进入预取范围后才由后端读取。图片字节在前端生成 Blob URL，离开有界 LRU 或会话关闭时立即撤销。

### 图片格式、限制与失败占位

首版只解码包内 PNG (`image/png`) 与 JPEG (`image/jpeg`)。每张图片的实际解码字节不得超过 16 MiB，图片头解析出的像素不得超过 32 MP，单会话前端图片 Blob LRU 不得超过 64 MiB；不得信任 ZIP 声明大小或压缩比。文档图片关系/块数量沿用统一条目上限并另设合理的文档块上限。图片 CRC、magic、MIME、路径或尺寸校验失败时，对应位置显示带安全短文件名和原因的占位，正文其它部分继续预览。

EMF/WMF、SVG、GIF、外链关系及未知格式不传给 WebView，统一显示“不支持的图片格式”占位。图片不进入正文关键词索引；可用的替代文字作为普通文本/图片说明返回并参与查找。

### 继承并收紧资源与安全边界

DOCX 继承统一归档的输入、实际解码字节、路径、扫描时间和 2 GiB 查看上限。实现还须拒绝 XML `DOCTYPE`/外部实体、加密 Office 容器、重复或缺失关键部件、CRC/ZIP/XML 错误及超过输出上限的转换结果；不得访问网络、跟随外部关系或把媒体释放到用户目录。内部文本缓存沿用应用缓存生命周期并在会话关闭/退出时清理。

格式检测只读取 ZIP 中央目录和必要的小型包元数据，不在监控扫描阶段解压主文档正文。正文以及可选的 `styles.xml`/`numbering.xml` 仅在用户打开时解析；可选部件仍受 XML、实际解码字节、路径和扫描时间上限约束，不得访问外部关系。

## Risks / Trade-offs

- 图文预览仍会丢失 Word 版式 → 在规格与界面中明确标注“简化预览”，只保证段落/标题/列表、表格网格与合并、图片锚点的稳定结构映射。
- 表格或编号定义可能复杂、损坏或使用自定义样式 → 对有限结构做严格有界解析，未知格式保留可见文字并安全回退，不因装饰信息阻断整份正文。
- WordprocessingML 的文本可能分散在多个 run → 事件流按顺序合并 `w:t`，不依赖 run 边界。
- 恶意 ZIP/XML 可能消耗资源 → 复用实际字节与时间上限，禁止外部实体，并以有界通道施加背压。
- 图片解码可能造成内存峰值或利用浏览器解析面 → 只允许 magic/MIME 一致的 PNG/JPEG，限制条目字节和像素，惰性读取并使用 64 MiB Blob LRU。
- 新 DOCX 会话扩大 IPC 与前端影响面 → 使用独立命令和判别式会话类型，保持既有日志命令兼容并执行前后端 L3 门禁。
- 增加直接 XML 依赖可能影响包体积/MSRV → 优先使用锁文件中已有、兼容 Rust 1.70 的轻量流式解析能力；实施任务包含依赖、构建和产物核对。

## Migration Plan

无需迁移持久化数据。升级后，新打开或恢复的有效 `.docx` 使用专用图文预览；普通 ZIP 与既有日志继续走原链路。回滚时移除 DOCX 格式注册、会话和前端预览组件即可，现有工作区中无法再打开的 DOCX 选项卡按普通来源不可用语义处理。

## Open Questions

- 无。首版范围固定为主文档的基础段落/标题/列表、结构化表格与包内 PNG/JPEG；字体颜色、精确版式、其它 Word 部件和图片格式留给后续独立 change。
