## ADDED Requirements

### Requirement: DOCX 简化图文预览

系统 SHALL 在现有选项卡工作区中以独立 DOCX 视图预览主文档正文与包内 PNG/JPEG。预览 SHALL 按主文档阅读顺序合并 `w:t` 文本，将普通正文、空段落、标题、1–3 级标题、项目符号/编号列表显示为独立语义段落，并保留显式换行和制表符；表格 SHALL 显示为带边框的真实行列与单元格，保留单元格内多段落并支持常见横向/纵向合并。图片 SHALL 出现在引用它的段落锚点附近并按块参与动态虚拟滚动。正文查找 SHALL 复用现有大小写、全词、方向和循环语义并覆盖段落、列表与单元格文字，但不提供日志行号、编码重建或字段筛选。

#### Scenario: 预览普通段落

- **WHEN** DOCX 主文档包含跨多个文本 run 的连续文字、多个普通段落、空段落、显式换行和制表符
- **THEN** 系统按阅读顺序合并 run，每个段落保持独立并使用可读的段前后间距，空段落保留垂直间隔，显式换行与制表符保留在所属段落内

#### Scenario: 预览标题和列表段落

- **WHEN** DOCX 使用直接段落属性或常见样式/编号定义标记标题、1–3 级标题、项目符号或十进制编号列表
- **THEN** 系统以清晰层级显示标题和列表标记；未知、自定义或损坏的样式/编号仍显示可见文字并安全回退为普通段落

#### Scenario: 预览表格

- **WHEN** DOCX 主文档包含多行多列表格且单元格内可能含多个段落、`w:gridSpan` 或 `w:vMerge`
- **THEN** 系统显示带边框的表格网格，保持行列与单元格段落，并将有效跨度映射为横向或纵向合并；缺失或冲突跨度回退为普通单元格且不丢失可见文字

#### Scenario: 大表格保持有界虚拟化

- **WHEN** 单个表格的行数或序列化体积超过单个预览块预算
- **THEN** 系统把表格拆成保持一致列结构的连续行组并按视口分页渲染，不一次性向 WebView 发送或挂载完整大表格

#### Scenario: 显示内嵌与浮动截图

- **WHEN** 主文档段落通过 `wp:inline` 或 `wp:anchor` 引用有效 PNG/JPEG
- **THEN** 预览在该段落锚点附近按文档顺序显示图片，保持纵横比且宽度不超过正文区域；浮动图片按块显示，不还原绝对坐标或文字环绕

#### Scenario: 图片替代文字

- **WHEN** DOCX 为图片提供名称、描述或替代文字
- **THEN** 预览将其作为图片说明和无障碍名称，并允许该文本参与正文查找

#### Scenario: 虚拟化浏览与查找

- **WHEN** 用户滚动或查找较大 DOCX 图文预览
- **THEN** 系统分页读取块并动态测量可见文本/图片高度，导航到匹配文本所在块，不一次性向前端发送、解码或渲染完整文档及全部图片

#### Scenario: 简化图片与版式

- **WHEN** DOCX 包含字体、颜色、主题、自定义复杂样式、精确列宽/分页、浮动环绕、图表、公式、批注、修订删除内容、字段指令、页眉页脚、脚注尾注、嵌入对象、宏或非 PNG/JPEG 图片
- **THEN** 首版不精确还原或执行这些能力；基础段落/标题/列表、表格结构、可见正文和支持图片继续显示，不支持图片在原锚点显示占位，界面明确这是简化预览

#### Scenario: 不支持旧 DOC

- **WHEN** 用户尝试打开旧二进制 `.doc` 或其它非 DOCX Word 格式
- **THEN** 系统不将其识别为 DOCX 预览，并明确提示该格式暂不支持

#### Scenario: DOCX 不显示日志专用控件

- **WHEN** DOCX 图文会话处于活动选项卡
- **THEN** 正文固定使用 UTF-8，界面不显示编码重建、日志字段筛选或行号控件，且用户操作不得以其它编码重新解释 DOCX 源包或转换流
