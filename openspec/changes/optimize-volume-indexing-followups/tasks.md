## 1. 架构优先

- [ ] 1.1 将查询索引 active/staging/previous 生命周期与文件系统切换逻辑抽取到 query store 边界，保持现有搜索行为不变。
  - **自测标准**：查询索引打开、部分查询、完整切换、遗留 `.next`/`.previous` 恢复和失败回滚单元测试通过；运行 Rust 格式检查、相关搜索测试和 Clippy，均无警告或失败。
- [ ] 1.2 将 SQLite schema/事务抽取到 persistence 边界，将 USN/启动恢复抽取到 recovery 边界。
  - **自测标准**：schema 初始化与升级、bulk 中断恢复、普通文件 USN、目录变化降级、旧路径删除和数据库锁回归测试通过；运行 Rust 格式检查、相关搜索测试和 Clippy。
- [ ] 1.3 将卷任务调度抽取到 coordinator、provider 边界，由 manager 只负责生命周期和对外操作，并建立 telemetry 边界。
  - **自测标准**：有界 worker、单 writer、按卷完成、单卷失败隔离、generation 取消和事件交接测试通过；完整 Rust 测试、前端测试、构建、格式和 Clippy 通过，Tauri 命令与事件载荷快照无变化。

## 2. 结构化观测

- [ ] 2.1 定义结构化 `IndexOperation` 与逐卷生命周期快照，以 operation ID 关联 generation、阶段时间、发现数、可搜索数、查询结果、错误和最终状态。
  - **自测标准**：单调时间、阶段切换、终态冻结、跨卷聚合、取消和失败状态单元测试通过；同一操作的所有 volume 记录均可通过 operation ID 关联且无负耗时或终态漂移。
- [ ] 2.2 由结构化快照生成完整性能报告，独立记录调度、provider 总耗时、查询可用、持久化、事件交接和状态收敛指标。
  - **自测标准**：使用成功、单卷失败、取消和持久化中断夹具生成报告；报告字段完整、计数与状态一致，不以零散日志或 MFT 子阶段替代完整生命周期。

## 3. 基线与真实 UI 验证

- [ ] 3.1 使用同一指标定义、设备、C:/D: 范围、Release 构建和固定数据快照，获取并归档修改前与当前版本各三次完整应用级基线。
  - **自测标准**：六个样本均包含完整 operation/volume 指标、发现数、可搜索数和代表性查询；数据规模差异在允许范围内，并明确给出三轮中位数，缺少任一完整样本不得完成。
- [ ] 3.2 在真实 Tauri/WebView 中采集搜索输入事件延迟，计算 p95 并验证不超过 100ms。
  - **自测标准**：索引建立和并发查询期间各完成三轮真实输入采样，保存原始样本数、采样方法和 p95；后端查询或 jsdom 数据不得计入验收。

## 4. 单卷恢复

- [ ] 4.1 为 `SearchIndexEntry` 和 Tantivy schema 增加规范化 exact `volume_key`，实现按卷 `delete_term` 与重建；segment 不作为正确性边界。
  - **自测标准**：不同卷同名路径、大小写规范化、按卷删除、不影响其它卷、删除后无旧路径和 segment merge 后语义一致的单元测试通过。
- [ ] 4.2 实现可回滚的查询索引 schema 迁移和 active/staging/previous 按卷发布，切换前核对逐卷计数与代表性查询。
  - **自测标准**：旧 schema 迁移成功、计数不一致拒绝发布、staging 失败、切换失败和 previous 回滚测试通过；失败时 SQLite 与旧 active 均保持可用。
- [ ] 4.3 完成单卷启动恢复并验证完整可搜索不超过 60 秒。
  - **自测标准**：固定数据快照上连续三轮恢复同一卷，目标卷旧路径全部删除、新路径完整命中、其它卷全程可查询；三轮均不超过 60 秒并记录 operation 报告。

## 5. Windows 切换可靠性

- [ ] 5.1 复核现有 active/staging/previous 重试与回滚实现，补充活动索引、并发查询、`.next`/`.previous` 状态、句柄占用和 operation ID 诊断。
  - **自测标准**：错误夹具能够断言阶段、源/目标路径、重试次数、目录状态和 operation ID；日志不记录文件内容，既有成功切换测试保持通过。
- [ ] 5.2 在活动索引、并发查询、遗留 `.next`/`.previous` 和外部占用场景下完成 Windows 真机复现与回归。
  - **自测标准**：每种场景至少成功执行三轮并归档诊断；有界占用释放后可完成切换，持续占用超过重试窗口时返回可定位错误而不假报成功。
- [ ] 5.3 验证切换失败后的旧索引查询与 UI 反馈。
  - **自测标准**：注入切换失败后，旧 active 的 C:/D: 代表性查询继续命中，UI 显示失败阶段和路径；重启恢复测试通过且不遗留不可判定的索引目录状态。
